```powershell

```

也可使用 `node create_guide.js "输出目录"` 指定位置。脚本默认输出到 docs；运行整理目录的 `_生成脚本/create_guide.js` 时，默认输出到上一级 `3-使用说明`。旧版 Word 不会被覆盖。

## 2026-11-12 曲线画布与应用范围修复

APPLY 只修改所选关键帧区段朝内的切线方向。例如选中前三帧中的前两帧，修改第一帧右侧和第二帧左侧，保留第二帧右侧至第三帧的曲线。单侧应用按当前方向设置处理；区段外的切线、权重及切线模式继续保留。CurveGuard 只保护登记的方向；Undo 或 Redo 后清空旧登记，避免恢复已撤销的曲线，需要重新 APPLY 才建立保护。

曲线预览使用固定画布，Logo、参数和 APPLY 分别占据各自区域。普通曲线沿用 Y=0～1；控制点超过这个范围时，自动扩大显示范围，同时容纳两个端点、黄色控制点及曲线。0 和 1 的参考线标明尺度；视图缩放只改变显示，不修改曲线参数。拖动采用稳定尺度，接近边缘时扩展，松手后平滑适配。

手动输入 Y 与原有拖动范围统一为 −2～3。READ 保留有限的原始 Y 值，超过该范围也可显示；横向拖动保持 Y，纵向拖动范围包含该次手势的起始值，未编辑的 READ 或预设值不再被重绘截断。关键帧移动改为 Offset / Ratio 两个互斥按钮，中文显示平移 / 比例，默认平移；点击当前模式保持勾选，切换模式清空勾选并重新扫描。平移和比例算法及零基准限制沿用现有规则。

## 2026-11-13 关键帧手动编辑兼容修复

修复 APPLY 后旧 CurveGuard 保护快照可能覆盖 Unity Animation 窗口手动编辑的问题。现在主动改变某一侧的切线值、权重、切线模式或 Broken 状态，或原地取消 Weighted，都会释放对应方向的保护；手改后再移动关键帧，也不会恢复旧 APPLY 数值。

自动恢复只用于一种明确情况：整条曲线只有一个关键帧的时间或数值变化，该方向所属关键帧自身发生了变化，而该侧切线、权重和模式未改、仅 Weighted 标志丢失。另一端移动不会重新恢复原地取消 Weighted 的方向。

CurveGuard 随观察更新最新位置快照；多关键帧移动或重排使对应关系不明确时，不自动覆盖修改。重新 APPLY 会建立新保护。

独立 Unity 2022.3.56f1c1 验证：18 份源码严格编译通过；冻结的 59 个用例、6987 项断言全部通过，旧 Guard 为 40 个用例、162 项断言失败；实际 AnimationWindow 选帧及 READ、APPLY、Undo/Redo 回归 937 项断言通过。手动修改通过原生 API 和实际 Guard 更新模拟。修复已接入 D 盘开发源码并保存于 feature/v1.0.4 的 aa304be；制作工程编译载入、物理鼠标拖动手感及制作场景人工试用仍待确认。正式版本字段仍为 1.0.3，v1.0.4 未发布。

### 2026年11月16日切线编辑后台修复

APPLY 现改为一次性写入，停止 CurveGuard 的后台自动恢复。应用后由 Unity 接管切线、权重和关键帧的后续编辑；移动关键帧时遵循 Unity 原生加权行为，不再自动套回最初的 Bézier 参数。选区内侧切线应用范围、READ 和关键帧移动工具继续保留。

修复已保存到 D 盘开发分支，源码提交 ea1041a。18 份源码通过严格编译，独立 c1 引擎的 29 阶段后台原生 API 检查通过，涵盖后续编辑、保存重载与 Undo／Redo。检查没有显示窗口或控制焦点。正式版本字段仍为 1.0.3，v1.0.4 未发布。
