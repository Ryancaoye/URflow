# v1.0.4 默认值对齐方案

日期：2026-10-29。状态：需求讨论与设计，尚未开始功能实现或 Unity 运行验证。

## 用户已确认的需求

- 动效制作完成后，交互会调整 UI 布局数值；希望一键让动画首帧或尾帧对齐新的默认值。
- 默认值是当前界面实例没有受到动画驱动时的静态布局值，不是动画预览采样值，也不以 Prefab 资源值替代。
- 只作用于 Animation 窗口中用户选中的属性曲线，不对整个动画片段的全部属性进行批量处理。
- 以同一偏移量整体移动该属性的全部关键帧数值，保持原来的动作幅度与缓动形状。

## 对齐行为

对每条选中的曲线独立计算：

- 首帧对齐：delta = 静态默认值 - 该曲线最早关键帧的 value。
- 尾帧对齐：delta = 静态默认值 - 该曲线最晚关键帧的 value。
- 全部关键帧：newValue = oldValue + delta，包括未单独选中的中间关键帧。

例如 X 原动画为 -200 → 0，静态 X 改为 50；尾帧对齐后为 -150 → 50。仅选 X 时 Y 不变；同时选 X/Y 时，各自计算偏移量。

保持关键帧数量、time、in/out tangent、in/out weight、weightedMode、切线模式、Broken 状态及曲线 wrap mode。不得通过已有 READ → APPLY 流程重建曲线，也不将新数值归一化或截断。

## 建议的操作方式，待讨论后实施

- 在 Animation 窗口选中需要处理的属性，例如 X 或 Y。
- 在 URFlow 提供“首帧对齐默认值”和“尾帧对齐默认值”两个操作。
- 首尾指各条选中属性曲线的最早/最晚关键帧，不以当前时间游标或局部选中帧作为端点。
- 对齐不要求至少选中两个关键帧；直接选中属性即可识别目标。
- 一次操作对应一次 Undo / Redo；重复点击已经对齐的端点不再产生修改。
- 普通预览开启时，先缓存目标、退出预览取得静态值，再完成对齐；可恢复普通预览和原时间位置，不自动重新开启录制。
- 无选中属性、找不到当前界面绑定对象、曲线只读或无法稳定获取默认值时给出明确提示。

首版具体支持哪些属性（UI 位移、缩放、透明度等）及按钮布局尚未最终确认；优先验证用户提出的 UI X/Y 位移场景。

## 技术核对结果与待验证边界

本次只读审查了仓库实现及 Unity 官方 2022.3 源码，没有执行 Unity 动态测试。

- 当前 URflowAnimHelper 主要识别同曲线至少两帧的关键帧选择；新功能需要独立获取选中属性的接口，不改变已有 READ/APPLY 规则。
- Unity AnimationWindowState 有 activeRootGameObject 和 selectedHierarchyNodes；停止预览前缓存 clip、root 和 bindings，避免预览状态变化后目标丢失。
- 通过当前 AnimationWindowState.StopPreview 使用窗口自己的 driver 退出预览；无参数 AnimationMode.StopAnimationMode 使用 DummyDriver，不能作为可靠替代。
- 退出正确预览 driver 后，可用 AnimationUtility.GetFloatValue(root, binding, out value) 读取属性；仍须动态验证是否准确还原交互更新后的静态布局值。
- 只改全部 key.value，不调用现有 Apply 来重算切线或用面板参数重新登记 CurveGuard。统一平移不会改变该曲线的 value 差值。
- Play Mode、其他持续动画驱动和自动布局驱动需要防护或进一步验证。对象引用、布尔/离散轨道、四元数旋转不能直接视为普通数值平移；无法可靠处理的属性须提示。

## 计划的验收场景

1. 修改界面静态 X/Y 后，在普通状态和 Animation 预览中执行首/尾对齐，读取结果均符合最新静态布局。
2. 三帧 X 为 [-200, -80, 0]，静态值 50；尾帧对齐结果为 [-150, -30, 50]。
3. 只选 X 时 Y、其他属性、其他对象及其他 clip 保持原数据；同时选 X/Y 则分别对齐。
4. 全部关键帧的时间、切线与权重元数据一致；验证普通、加权和阶梯曲线。
5. CurveGuard 有登记及无登记时都保持曲线形状，等待编辑器更新后不恢复成旧位置。
6. 一次 Undo 完整恢复，一次 Redo 重做；已对齐时重复点击没有变化。
7. 非法或不支持目标得到提示，原动画数据受到保护。

以上是待执行的验收计划，不是已通过的测试结果。
