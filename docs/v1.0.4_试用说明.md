# URFlow v1.0.4 关键帧移动试用说明

这是 v1.0.4 开发分支的关键帧移动功能，通过统一页面检查当前片段的首帧或尾帧与静态默认值，并只对明确勾选的曲线应用移动。稳定目录与正式标签仍为 v1.0.3，开发包的正式版本字段尚未更新；不要仅凭窗口页脚版本判断是否加载了新功能，应确认开发包路径并看到“关键帧移动”入口。

## 在现有项目工程中使用

本功能可以在正常 Unity 项目中使用。独立工程用于开发时的编译、曲线写入和撤销验证，不是使用要求。

根据项目当前的安装方式更新，项目内只保留一份 URFlow：

- 原先复制到 `Assets`：先把旧插件留一份副本在 `Assets` 外，再将开发目录 `D:\插件\URFLOW\6-开发\URflow-v1.0.4\Editor` 的内容更新到项目原 URFlow 的 `Editor` 目录，保留 `.meta`。这一版是在原代码上新增模块，不需要另建一个 URFlow 文件夹。
- 原先通过 Package Manager 安装：将原 URFlow 的包依赖改为开发目录的本地包。可在 Package Manager 的 `+ > Add package from disk` 选择 `D:\插件\URFLOW\6-开发\URflow-v1.0.4\package.json`。若 `Assets` 里还有复制安装的旧版，先把它移出 `Assets`，避免重复程序集。

等待 Unity 编译后，打开 `Window > URflow`，看到预设下方“关键帧移动”入口即可。首次试用可复制一份现有 `.anim` 并临时关联该副本，确认首尾对齐及 Undo/Redo 的结果，再用于制作中的动画。

开发版仍有完整界面和视觉验收待完成，已验证范围见开发记录。不要把 `Tests~` 内的验证脚本导入制作工程；它们只用于开发验证。

更新或代班后入口消失时，先检查 Package Manager 是否仍有 URFlow。开发包可重新选择 Add package from disk，指向 D:/插件/URFLOW/6-开发/URflow-v1.0.4/package.json；Packages/manifest.json 应有 com.liuyiran.urflow 的 file:D:/插件/URFLOW/6-开发/URflow-v1.0.4 引用。只保留一份安装，等 Unity 编译/脚本重载结束再查看 Window > URflow。还原工程配置可能移除本地引用，普通 SVN update 并非必删；本地路径不是已提交到团队SVN的保证。

## 统一检查与勾选应用

1. 在没有 Animation 驱动时，将界面实例的位置、尺寸或缩放设置为需要的静态布局值，并将该实例和动画片段关联到当前 Animation 窗口。
2. 打开 `Window > URflow`，点击底部 Move 工具。统一页面直接扫描当前片段的全部位置、RectTransform Size Delta 与缩放曲线，不需要先选 Animation 属性。
3. 上方选择 First Frame 或 Last Frame，默认尾帧。它们分别是每条曲线的最早和最晚关键帧；基准选项共同用于扫描和应用。默认整体平移，需要按比例改变动作幅度时开启整行 Proportional（按比例调整）按钮；开启时黄色高亮并标示倍率，关闭时标示平移。
4. 按对象分组查看基准帧值、静态默认值和差值。列表只显示差异及无法处理项，初始全部未勾选；已一致项隐藏，无法处理项显示原因且不可勾选。
5. 可搜索对象或属性。双击对象标题或属性行中复选框之外的区域（如数值），可在 Hierarchy 中闪亮定位目标对象，保留 Unity 当前选中对象与 Animation 编辑状态；目标缺失时会提示。
6. 逐项或按对象组勾选，Select Shown 选择当前搜索结果中可处理的差异，Clear 清空全部勾选。核对 Apply (N) 的总数再应用，整条勾选曲线一同变化；一次 Undo/Redo 对应这整批修改。
7. 点击 Rescan 可重新读取默认值和结果；首尾或比例模式改变、重扫及 Undo/Redo 刷新会清空勾选。应用后自动重扫，达到一致的曲线从默认差异列表中消失。
8. 关闭按钮或 Escape 使用 280 ms 淡出和轻微下移返回曲线界面；开始关闭即取消尚未执行的扫描或应用回调。原曲线参数、预设筛选与滚动状态保留。

搜索保留当前搜索结果外的勾选，并显示隐藏数量与 Apply (N) 总数。首尾基准或比例模式改变、重扫及 Undo/Redo 刷新会清空勾选。工具始终扫描当前片段全部支持属性，列表勾选决定最终写入范围，不受 Animation 属性选择限制。

位置与 Size Delta 绝对差不超过 0.0001、缩放绝对差不超过 0.000001，扫描视为浮点尾差已一致。超过阈值的真实小差异仍列出，继续显示非零差值；端点按 G6 格式显示，数值提示以 R 格式保留完整精度。已一致行隐藏，列表始终展示差异及无法处理项。应用时基准关键帧写入精确默认值。容差不放宽过期曲线和静态值检查。数值差异可能是有意设计，并非错误判定。

缺失目标、布局或其他预览驱动、无效数据、比例零基准等项目显示原因并禁止勾选。不相关的无效项目不阻止其他有效勾选项应用；拉伸轴必需的配对项目无效时拒绝该次应用。扫描不写动画；应用前重新核对当前对象、片段、属性集合、勾选曲线和默认值，过期结果必须重新扫描。


## 拉伸布局的当前操作

Top / Bottom 或 Left / Right 由 Anchored Position、Size Delta 和 Pivot 共同决定。Y 轴 Pivot 为 0.5 时，Top 50、Bottom 80 对应 Anchored Position Y 为 15、Size Delta Y 为 -130；位置对齐为 15 而尺寸仍为 -100，就会得到 Top 35、Bottom 65。截图中的 80 和 -160 未确定采样时间，不能据此声称它们是错误结果的同一尾帧。

统一页面增加 RectTransform 的 UI Size X / Y（Size Delta）曲线，和 UI Pos X / Y 一起显示基准帧值、静态默认值及差值。它们是尺寸偏移，不是 Scale。首帧、尾帧、整体平移及比例选项沿用当前操作；尺寸差异使用与位置相同的 0.0001 绝对容差。

拉伸轴的位置与尺寸都有差异时，请明确勾选同一对象、同一轴的两项再应用。例如垂直拉伸应同时勾选 UI Pos Y 和 UI Size Y。缺少配对差异项时整次应用拒绝写入并显示提示，不自动扩大勾选、不修改搜索结果外未勾选项。

同轴配对已经一致时可以只改仍有差异的一项；没有配对动画轨道时使用静态值，不创建新曲线。非拉伸轴的位置与 Size Delta 允许独立处理。其他轴、其他对象和未勾选曲线保持原状；一次 Undo / Redo 仍对应整批写入。

比例模式对 Size Delta 的原始数值计算倍率。实际宽高还包含父矩形与锚点跨度，因此这不代表界面的实际宽高按同一比例缩放。负 Size Delta 是合法布局数值；比例基准为零而目标非零时仍拒绝计算。曲线时间、关键帧数、切线模式、Broken、权重及 wrap mode 保留。

锚点或 Pivot 自身带有动画时，本轮不支持完整位置与尺寸对齐，相关行显示原因并禁止应用；Scale 行仍按原规则处理。自动布局驱动的尺寸与位置不作为可靠静态默认值。扫描后锚点、Pivot、勾选曲线或默认值发生变化时要求重新扫描，应用前在暂停当前预览的状态重新核对同轴配对。

## 两种规则

- 整体平移：`-100 → 100`，尾帧默认值 `200`，得到 `0 → 200`；有限切线斜率和数值差保持。
- 按比例调整：相同位置曲线得到 `-200 → 200`；缩放 `0 → 1`、尾帧默认值 `1.5`，得到 `0 → 1.5`。动作幅度会改变，有限切线斜率同乘倍率。

两种模式都保留时间、关键帧数量、切线模式、Broken、权重及 wrap mode。首/尾指整条曲线的最早/最晚关键帧。

## 首版边界

- 当前支持 Transform/RectTransform 的本地位置、UI anchored position、RectTransform Size Delta X/Y 与本地缩放；旋转和透明度不在本版范围。
- 扫描当前片段全部支持属性；Animation 窗口的属性选择不限制扫描范围，应用只处理工具列表中明确勾选的差异项。
- 只应用工具列表中明确勾选的有效差异项；不相关的未勾选无效项目不会阻止应用，拉伸轴必需的配对项目仍统一校验。所有勾选项在写入前校验，过期结果须重新扫描。
- 比例基准为 0、默认值非 0时不能计算倍率。二者都为 0时已对齐，不产生修改。零倍率与负倍率在面板中明确提示，应用后分别归零或反转数值。
- 自动布局驱动的目标轴、其他动画预览驱动、运行模式和不可编辑动画会提示原因。
- 读取默认值时退出当前 Animation 窗口自身预览，随后恢复普通预览及原时间；录制状态保持关闭，避免自动增加关键帧。

## 2026-11-12 曲线画布与应用范围修复

APPLY 只修改所选关键帧区段朝内的切线方向。例如选中前三帧中的前两帧，修改第一帧右侧和第二帧左侧，保留第二帧右侧至第三帧的曲线。单侧应用按当前方向设置处理；区段外的切线、权重及切线模式继续保留。CurveGuard 只保护登记的方向；Undo 或 Redo 后清空旧登记，避免恢复已撤销的曲线，需要重新 APPLY 才建立保护。

## 2026-11-13 关键帧手动编辑兼容修复

修复 APPLY 后旧 CurveGuard 保护快照可能覆盖 Unity Animation 窗口手动编辑的问题。现在主动改变某一侧的切线值、权重、切线模式或 Broken 状态，或原地取消 Weighted，都会释放对应方向的保护；手改后再移动关键帧，也不会恢复旧 APPLY 数值。

自动恢复只用于一种明确情况：整条曲线只有一个关键帧的时间或数值变化，该方向所属关键帧自身发生了变化，而该侧切线、权重和模式未改、仅 Weighted 标志丢失。另一端移动不会重新恢复原地取消 Weighted 的方向。

CurveGuard 随观察更新最新位置快照；多关键帧移动或重排使对应关系不明确时，不自动覆盖修改。重新 APPLY 会建立新保护。
